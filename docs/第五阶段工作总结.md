## 工作内容

### 1. 模块架构设计

基于「分层解耦、可靠性优先」的架构原则，消费层采用「三消费者并行 + 双数据库存储」架构：

```
ecg_vital 队列 → 生命体征消费者 → PostgreSQL
ecg_wave 队列  → 波形消费者（攒批）→ TDengine
ecg_alarm 队列 → 报警消费者 → PostgreSQL
```

### 2. 消费者框架（monitor-consumer/src/consumer/）

#### 2.1 基类 BaseConsumer [base.rs](file:///d:/Code/Monitor/monitor-consumer/src/consumer/base.rs)

**核心功能：**
- MQ 连接与通道管理
- QoS 预取数量配置
- 手动 ACK / NACK 操作
- 队列声明（确保存在）
- 消费者标签管理

**可靠性保障：**
- ✅ 手动 ACK（`no_ack: false`）
- ✅ NACK 不重新入队（`requeue: false`），自动转入死信队列
- ✅ 预取数量流控（防止消费速度跟不上导致内存堆积）

#### 2.2 生命体征消费者 [vital_consumer.rs](file:///d:/Code/Monitor/monitor-consumer/src/consumer/vital_consumer.rs)

**消费流程：**
```
接收消息 → JSON 解析 → 重试写入 PostgreSQL → 成功 ACK / 失败 NACK
```

**特性：**
- 写入失败自动重试（默认 3 次，间隔 1 秒）
- 解析失败直接 NACK 转入死信
- 每 100 条输出统计日志

#### 2.3 波形消费者 [wave_consumer.rs](file:///d:/Code/Monitor/monitor-consumer/src/consumer/wave_consumer.rs)

**消费流程：**
```
接收消息 → 解析波形 → 攒批 → 批量写入 TDengine → 批量 ACK / NACK
```

**批量策略：**
- 触发条件：数量达到 100 条 **或** 等待超过 1 秒
- 批量 ACK：使用 `multiple=true` 一次性确认整批
- 批量 NACK：整批失败统一转入死信

**优势：**
- 大幅减少数据库写入次数（从 100 次 → 1 次）
- 显著提高吞吐
- 符合 TDengine 「批量写入」的最佳实践

#### 2.4 报警消费者 [alarm_consumer.rs](file:///d:/Code/Monitor/monitor-consumer/src/consumer/alarm_consumer.rs)

**消费流程：**
```
接收消息 → JSON 解析 → 重试写入 PostgreSQL → 成功 ACK / 失败 NACK
```

**特性：**
- 高优先级处理（报警数据量小但重要）
- 每条报警都有详细日志
- 失败重试机制与生命体征一致

### 3. 存储层（monitor-consumer/src/storage/）

#### 3.1 TDengine 时序库 [tdengine.rs](file:///d:/Code/Monitor/monitor-consumer/src/storage/tdengine.rs)

**架构设计：**
- **超级表**：`ecg_waveform`（统一 schema）
- **子表**：按「床位 + 导联」划分，命名如 `wave_bed1_leadii`
- **标签**：床位号、导联类型、采样率、设备 IP、厂商

**表结构：**
| 字段 | 类型 | 说明 |
|------|------|------|
| ts | TIMESTAMP | 时间戳（主键） |
| sample_value | BINARY(10240) | 采样值（hex 编码） |

**存储策略：**
- KEEP 365 天（数据保留 1 年）
- DURATION 10 天（文件组周期）
- BUFFER 16MB（内存缓冲区）
- COMP 1（一阶段压缩）

**核心方法：**
- `init()` — 创建数据库、超级表
- `insert_waveforms()` — 批量写入（按床位+导联分组）
- `query_waveforms()` — 按时间范围查询

#### 3.2 PostgreSQL 关系库 [postgres.rs](file:///d:/Code/Monitor/monitor-consumer/src/storage/postgres.rs)

**连接池：**
- deadpool-postgres 连接池
- 池大小可配置（默认 10）
- 获取/创建/回收超时控制

**表结构：**

**生命体征表 `vital_signs`**
- 字段：ts, bed_no, device_ip, vendor, model, serial, heart_rate, pulse_rate, spo2, resp_rate, nibp_*, temperature
- 索引：`(bed_no, ts DESC)` 联合索引、`(ts DESC)` 时间索引

**报警事件表 `alarm_events`**
- 字段：ts, bed_no, device_ip, vendor, alarm_code, alarm_name, priority, event_phase, trigger_*, low_limit, high_limit
- 索引：`(bed_no, ts DESC)`、`(ts DESC)`、`priority`

**设备信息表 `devices`**
- 字段：device_ip（唯一）、bed_no、vendor、model、serial、first_seen、last_seen、is_online
- upsert 自动维护设备在线状态

### 4. 主程序 [main.rs](file:///d:/Code/Monitor/monitor-consumer/src/main.rs)

**启动流程：**
1. 初始化日志
2. 加载配置（环境变量 + 默认值）
3. 初始化 PostgreSQL（同步等待，确保就绪）
4. 初始化 TDengine（异步后台，不阻塞启动）
5. 启动 3 个消费者任务（生命体征、波形、报警）
6. 监听 Ctrl+C 优雅停机

**优雅停机：**
- 捕获 Ctrl+C 信号
- abort 所有消费者任务
- 500ms 清理时间

### 5. 配置管理 [config.rs](file:///d:/Code/Monitor/monitor-consumer/src/config.rs)

**配置项：**
- 消费者配置：消费者组前缀、预取数量、重试次数、批量参数
- TDengine 配置：主机、端口、用户名、密码、数据库、超时
- PostgreSQL 配置：主机、端口、用户名、密码、数据库、连接池大小
- 支持 `MONITOR_CONSUMER_` 环境变量前缀
