## 工作内容

### 1. 模块架构设计

基于 Tokio 异步 TCP 服务，采用「事件驱动 + 每设备独立任务」架构，符合项目「零丢包、低延迟」设计目标。

| 模块 | 文件 | 职责 |
|------|------|------|
| 配置管理 | [config.rs](file:///d:/Code/Monitor/monitor-access/src/config.rs) | 监听地址、端口、超时、连接数等配置 |
| 事件定义 | [event.rs](file:///d:/Code/Monitor/monitor-access/src/event.rs) | 设备上线/下线、数据接收、解析错误等事件 |
| 连接处理 | [connection.rs](file:///d:/Code/Monitor/monitor-access/src/connection.rs) | 单连接读取循环、帧解析、消息解析 |
| 设备管理 | [device_manager.rs](file:///d:/Code/Monitor/monitor-access/src/device_manager.rs) | 连接池管理、设备注册/注销、统计 |
| TCP 服务器 | [server.rs](file:///d:/Code/Monitor/monitor-access/src/server.rs) | 监听连接、任务分发 |
| 服务入口 | [main.rs](file:///d:/Code/Monitor/monitor-access/src/main.rs) | 启动服务、日志、事件消费示例 |

### 2. 核心功能实现

#### 2.1 TCP 服务器
- 基于 Tokio 异步运行时，单端口监听
- 五元组（IP）区分不同设备
- 每设备独立 Tokio 任务，互不阻塞
- 连接数上限控制（默认 1000）
- 优雅停机支持（Ctrl+C 信号处理）

#### 2.2 设备连接处理
- 异步 BufReader 缓冲读取
- 超时检测（默认 300 秒无数据自动断开）
- 集成 monitor-proto 帧解析器，流式帧切分
- HL7 消息解析与标准化输出
- 解析错误事件上报

#### 2.3 设备管理器
- 线程安全的设备连接表（RwLock<HashMap>）
- 设备上线/下线事件
- 连接状态跟踪（连接时间、最后活动时间、消息计数）
- 连接数统计查询

#### 2.4 事件系统
- 统一事件枚举 `AccessEvent
- mpsc 通道异步事件传递
- 事件类型：
  - `DeviceConnected` - 设备上线
  - `DeviceDisconnected` - 设备下线（含断开原因）
  - `VitalSignsReceived` - 生命体征数据
  - `WaveformReceived` - 波形数据
  - `AlarmReceived` - 报警事件
  - `ParseError` - 解析错误

### 3. 配置管理
- 支持环境变量配置（`MONITOR_ACCESS_` 前缀）
- 默认配置：
  - 监听地址：0.0.0.0:9000
  - 连接超时：300 秒
  - 最大连接数：1000
  - 接收缓冲区：8192 字节
