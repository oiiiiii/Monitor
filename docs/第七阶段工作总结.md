# 第七阶段工作总结：WebSocket 推送服务

## 一、阶段目标

完成 WebSocket 实时推送服务（monitor-push），实现：
1. 从 RabbitMQ 消费三类数据（生命体征、波形、报警）
2. 通过 WebSocket 向订阅客户端推送实时数据
3. 按床位维度进行订阅管理
4. 心跳检测与连接管理
5. 报警优先推送机制
6. 与前端的数据协议规范

## 二、完成内容

### 2.1 项目结构
```
monitor-push/
├── Cargo.toml
└── src/
    ├── main.rs              # 服务入口
    ├── config.rs            # 配置管理
    ├── pipeline.rs          # MQ 消费管道
    └── websocket/           # WebSocket 模块
        ├── mod.rs
        ├── message.rs       # 消息协议定义
        ├── session.rs       # 客户端会话管理
        └── server.rs        # WebSocket 服务器
```

### 2.2 核心功能

#### 1. 消息协议（message.rs）
- **ClientMessage**：客户端消息
  - `subscribe(bed_no)`：订阅床位
  - `unsubscribe(bed_no)`：取消订阅
  - `ping`：心跳检测
- **PushMessage**：服务端推送消息
  - `VitalSigns`：生命体征数据
  - `Waveform`：波形数据
  - `Alarm`：报警事件
  - `Error`：错误消息
  - `Pong`：心跳响应

#### 2. WebSocket 服务器（server.rs）
- 基于 `tokio-tungstenite` 实现
- 支持多客户端并发连接
- 客户端 ID 生成与管理
- 连接数限制（默认 100）
- Ping/Pong 心跳检测
- 优雅关闭

#### 3. 客户端会话（session.rs）
- `ClientSession`：单个客户端会话
  - 订阅/取消订阅床位
  - 心跳超时检测（默认 30s）
  - 消息发送通道
- `ClientManager`：客户端管理器
  - 客户端注册/注销
  - 按床位广播消息
  - 全局广播
  - 连接数统计

#### 4. MQ 消费管道（pipeline.rs）
- 从 RabbitMQ 消费三类消息
- 消费后通过 `ClientManager` 推送给订阅客户端
- 报警优先推送策略
- 失败重试机制

#### 5. 配置管理（config.rs）
- WebSocket 监听地址
- 心跳间隔
- 连接数限制
- MQ 配置复用

## 三、关键设计

### 3.1 订阅模型
- 采用「床位维度」订阅
- 一个客户端可订阅多个床位
- 一个床位可被多个客户端订阅
- 使用 `HashMap<u16, HashSet<ClientId>>` 维护订阅关系

### 3.2 并发模型
- `tokio::spawn` 每个客户端连接独立任务
- MQ 消费独立任务
- 客户端管理器全局共享（`Arc<Mutex<ClientManager>>`）
- 使用 `mpsc::channel` 进行线程间消息传递

### 3.3 心跳机制
- 服务端每 10s 发送 Ping
- 客户端 30s 未响应 Pong 则断开
- 客户端也可主动发送 Ping
